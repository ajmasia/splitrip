## 1. Taking backups

- [ ] 1.1 Write `deploy/backup.sh`, installed as `backup` beside `update`, that refuses anybody but the superuser and writes `splitrip-<UTC timestamp>-<kind>.tar.gz` to a `700` `/opt/splitrip/backups/` with `database.dump` (`pg_dump --format=custom` of the whole database), `splitrip.env` and `manifest`, file mode `600`, printing its path, and pruning the backups of its own kind; verify on the instance that a backup taken while a phone uses the application leaves it answering, that the file's mode and contents are as described, that `pg_restore --list` reads the dump, that a non-root run is refused, and that `shellcheck` reports nothing
- [ ] 1.2 Add the daily `splitrip-backup.timer`, persistent, with its service running `backup` as the `daily` kind, installed by the installer and by `update`; verify on the instance that `systemctl list-timers` shows it, that starting its service writes a daily backup, and that daily backups dated more than seven days ago (made so with `touch`) are removed by the next one while a `manual` one of the same age stays
- [ ] 1.3 Take an `update` backup in `update` before applying the migrations, keeping the newest three, and none when moving back; verify by updating the instance to a new candidate that the backup is written before the migrations step, that a fourth update leaves three, that moving back takes none, and that with the backup directory made unwritable `update` stops at that step with the previous release still serving

- [ ] 2.1 Make the installer read `SPLITRIP_RESTORE`: check the tar, its manifest and its dump before anything else, refusing an unknown format, a damaged file or a release older than the first one able to restore; install the manifest's release with the backup's `splitrip.env`; restore the dump with `pg_restore --clean --if-exists --exit-on-error` after `bootstrap.sql` instead of applying migrations; and create no first account; verify that a text file, a truncated backup and a backup of an unsupported format are refused before any package is installed, and that `shellcheck` reports nothing
